# ADR-002: 算力固存机制

## 状态

已接受

## 背景

核心问题：当没有消费者时，挂机贡献者的算力无法被衡量和利用。

三个子问题：
1. **无法衡量**：没有用户任务时，节点"挂机"贡献怎么验证？（光说"我在线"容易作弊）
2. **算力浪费**：空闲算力能否转化为持久价值？（类比水力发电，没人用电时水势能浪费）
3. **强度可调**：怎么不影响贡献者的本地正常使用？

## 决策

采用三层机制：

### 1. PoA 探针（Proof of Availability）

协调器定期向空闲节点发送轻量探针任务（几秒内完成的小计算）。探针成功 = 证明节点真的在线、资源真实可用、愿意执行。贡献分公式引入探针成功率系数。

### 2. 算力固存（Compute Solidification）

池空闲且无用户任务时，调度器自动派发填充任务，把算力转化成持久价值：
- 预计算缓存：热门模型推理结果预存
- 社区模型训练：池化 GPU 渐进训练社区模型
- BOINC 志愿计算：接入公益项目
- 镜像预构建：常用任务模板 Docker 镜像提前构建

填充任务也算真实贡献，产物可被后续用户复用。

### 3. 强度可调

Agent 监测本地负载，用户设保守/均衡/激进档位，动态调整上报资源量。

## 后果

**优势：**
- 挂机即贡献成为可验证事实（PoA 探针）
- 空闲算力不浪费（固存为持久产物）
- 不影响本地使用（强度可调 + 负载感知）
- 填充任务可被用户任务随时抢占（优先级保证）

**风险：**
- 探针增加协调器负载——探针极轻（几秒小计算），可接受
- 填充任务产物占用存储——需要淘汰策略（列为待决事项）
- 社区模型训练方向需社区共识——列为待决事项

**抢占优先级：** 填充任务 > 弹性用户任务 > 份额内用户任务（填充任务最先被抢占让出）
